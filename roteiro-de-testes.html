Preparar o ambiente

Suba a aplicação e confira que o banco tem os dados de exemplo. Leva menos de um minuto e evita que você confunda um bug com um ambiente pela metade. 

# na raiz do projeto
$ docker compose up

A aplicação sobe em localhost:4000. O compose roda mix ecto.setup a cada subida, então banco, migrations e seeds já vêm prontos.

Se o container já estava rodando antes desta branch, faltam migrations: as tabelas bands e band_members podem não existir, e o índice que torna o nome de banda único é novo. Aplique as migrations e recarregue os seeds: 

$ docker compose exec app mix ecto.migrate
$ docker compose exec app mix run priv/repo/seeds.exs

Se o banco ainda tem a Ana Pastora ou a Banda Jovem, ele é de antes desta branch. Os seeds trocaram de gente e de bandas, e rodá-los de novo só acrescenta o que falta — o que já estava lá continua, com os nomes antigos. Zere o banco para começar do estado descrito aqui embaixo (a aplicação precisa estar parada, como explica Recomeçar do zero): 

$ docker compose stop app
$ docker compose run --rm app mix ecto.reset
$ docker compose up

A US 1.9 trouxe dependências novas (o salad_ui e companhia) e tirou o daisyUI. O container guarda deps e _build em volumes próprios, então suba de novo do zero para que ele as baixe — sem isso a aplicação nem compila: 

$ docker compose down
$ docker compose up --build

US 1.4

Músicos e vínculo a bandas

Quem responde por uma banda monta o elenco dela: escolhe na lista um músico que já tem conta ativa e diz o que ele faz ali. O mesmo músico entra em quantas bandas quiser, com função própria em cada uma — mas uma vez só por banda. O Líder de Banda também sobe para tocar, então entra no elenco desde o primeiro dia e precisa de função como qualquer um.

Quatro linhas com "não" na coluna toda são de propósito. Mudar o próprio papel de acesso ninguém muda: promover e rebaixar é sempre decisão de outra pessoa, e nem quem tem acesso total escapa disso. Quando algo dá errado

As telas carregam, mas nada responde

Botões mortos, formulários que não enviam, Sair caindo em erro de rota: quase sempre é o bundle de JavaScript faltando. Confirme e reconstrua: 

# tem que responder 200, não 404
$ curl -o /dev/null -w '%{http_code}\n' localhost:4000/assets/js/app.js
$ docker compose exec app mix assets.build

Erro dizendo que uma tabela não existe

Alguma migration não foi aplicada no seu banco de desenvolvimento — bands veio com a US 1.3 e band_members com a US 1.4: 

$ docker compose exec app mix ecto.migrate

Recomeçar do zero

Derruba o banco, recria, migra e recarrega os seeds. Você perde tudo que criou testando — que é justamente a intenção quando o roteiro embolou. A aplicação precisa estar parada: mix ecto.drop não derruba um banco com conexões abertas, e ela mantém as dela enquanto estiver de pé. 

$ docker compose stop app
$ docker compose run --rm app mix ecto.reset
$ docker compose up

Rodar a suíte automatizada

366 testes cobrem os mesmos caminhos deste roteiro. Rodar antes de testar na mão poupa tempo: se a suíte quebra, o problema não está no seu clique. 

$ docker compose exec app mix test
# compila sem warnings, formata e roda os testes
$ docker compose exec app mix precommit

Cobre as US 1.1 a 1.9 da Fase 1. As marcações ficam guardadas neste navegador e sobrevivem a recarregar a página — Limpar marcações zera tudo. Ao entregar uma funcionalidade nova, este roteiro é atualizado junto, no mesmo Pull Request.
